# Golden Arrows Dataset V3.0

Golden Arrows Dataset V3.0 is a simulation-generated multi-drone swarm
dataset for research in:

- swarm intelligence and autonomous multi-agent systems
- swarm behavior and network-aware coordination
- mission intelligence and multi-agent decision making
- reinforcement learning and machine learning for swarm systems
- behavior-aware learning

It is **not real-world flight data** and does not provide real-world flight
validation. The records were generated by the Golden Arrows simulation using
a scripted mission controller with advanced swarm behavior.

## Verified dataset summary

The values below are taken from the V3 metadata, independent audit, and
analysis reports in `datasetv3_final`.

| Item | Verified value |
| --- | --- |
| Schema version | `golden_arrows_v3_rich_transition_1.0` |
| Missions | 100 |
| Transitions | 11,570 |
| Drone-transition records | 347,100 |
| Drones per transition | 30 |
| Completed missions | 100/100 |
| Simulation time step | 0.5 |
| Mission split | 25 PATROL, 25 SURVEILLANCE, 25 SEARCH, 25 RECOVERY |
| Policy representation | `SCRIPTED_MISSION_CONTROLLER+ADVANCED_SWARM_BEHAVIOR` |
| Advanced behavior | Enabled for all 11,570 transitions |
| Behavior mode | `BOUNDED_CORRECTION_ON_MISSION_MOTION` |

The transition-level action is deterministic by mission type in this release:
`PATROL_MOVE`, `SURVEILLANCE_MOVE`, `SEARCH_MOVE`, or `RECOVERY_MOVE`.
This is a property of the logged scripted controller, not evidence of learned
policy diversity.

## Data layout

The populated source and derived files are under `datasetv3_final/`:

```text
datasetv3_final/
├── processed/transitions/       # 100 transition JSONL files
├── raw/missions/                # 100 raw mission JSON files
├── metadata/
│   ├── collection_config.json
│   ├── dataset_summary.json
│   └── mission_index.jsonl
├── reports/
│   └── pilot_validation_report.json
├── analysis_v3_decision_action/
├── analysis_v3_ml_readiness/
├── analysis_v3_state_action_outcome/
├── ml_ready/
├── ml_ready_state_only/
└── ml_ready_behavior_aware/
```

Each processed transition file contains one JSON object per line. A record
includes mission metadata, transition timing, the controller decision, the
logged action, network results, and a `swarm` object containing 30 drones.
Drone records include pre-transition position, post-transition physical and
network state, actual movement, and advanced-behavior values.

The raw mission files retain the mission-level JSON representation. The
processed JSONL files are the source used by the derived ML-ready exports.

## Mission and transition content

The four mission types are balanced by mission count:

| Mission type | Missions | Transitions |
| --- | ---: | ---: |
| PATROL | 25 | 6,461 |
| SURVEILLANCE | 25 | 2,266 |
| SEARCH | 25 | 1,180 |
| RECOVERY | 25 | 1,663 |

The transition records expose, among other fields:

- mission type, mission status, progress, waypoint and target metadata
- transition tick and `dt`
- active links and connected drones
- controller policy, assignments, action type and behavior mode
- per-drone position, altitude, speed, direction, battery and network state
- advanced-behavior summaries and seven behavior components:
  cohesion, alignment, separation, formation, target attraction,
  network preservation, and boundary avoidance

## Derived ML-ready exports

Three derived export families are present:

- `ml_ready/`: the general V3 ML-ready export
- `ml_ready_state_only/`: the state-only baseline
- `ml_ready_behavior_aware/`: the state-plus-advanced-behavior export

Each family contains `train.csv`, `validation.csv`, `test.csv`,
`feature_schema.json`, and a preparation report (the behavior-aware family
also contains a state-timing audit).

All exports use a mission-level stratified split with seed `20260916`:

| Split | Missions | Rows |
| --- | ---: | ---: |
| Train | 68 (17 per type) | 234,600 |
| Validation | 16 (4 per type) | 58,860 |
| Test | 16 (4 per type) | 53,640 |

The state-only export has 13 input features and predicts
`next_position_x` and `next_position_y`. The behavior-aware export adds the
verified advanced-behavior features and has 55 input features, with the same
two targets. The behavior-aware export contains 42 behavior fields as
enumerated in its `feature_schema.json`.

The exported features include fields logged under `state_after` in the V3
source, including altitude, speed, direction, battery, signal strength,
latency, and packet loss. They are preserved because they are part of the
verified record, but they must not automatically be treated as strict
pre-action observations in causal or reinforcement-learning experiments.
For such experiments, establish timing explicitly; the audit recommends
pre-action/context fields plus advanced-behavior features and excluding
`actual_movement`, `action`, `decision`, and `progress_after` from inputs.

## Validation and analyses

The included reports independently verify:

- source coverage and exact 30-drone transition cardinality
- presence of raw and processed mission files
- mission completion and advanced-behavior activation
- decision/action distributions
- state-action-outcome relationships
- feature coverage, correlations, and leakage candidates
- ML-ready split integrity and state-timing limitations

These analyses are descriptive and validation-oriented. They are not model
performance evaluations, causal estimates, or evidence of real-world
operational effectiveness.

## Important snapshot note

The populated and audited data are currently located in `datasetv3_final/`.
The top-level publication wrapper contains the expected folder names, but some
wrapper artifacts (including the top-level documentation, schemas, and example
files) are empty in this snapshot. This README therefore documents the files
and values that are actually present rather than claiming that those empty
artifacts provide additional schema definitions or runnable preprocessing
code.

## Reproducibility and data integrity

The reports state that Dataset V3 source files and the frozen Dataset V2.2
baseline were not modified during analysis and preparation. The metadata
records the collection configuration, including the fixed collection seed
`20260916`, `dt = 0.5`, and `max_steps = 1000`.
