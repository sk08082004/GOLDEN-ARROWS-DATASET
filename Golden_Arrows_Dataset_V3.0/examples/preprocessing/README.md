# Optional Preprocessing Examples

## 1. Overview

This directory contains implemented, optional preprocessing examples for
transforming the authoritative Golden Arrows Dataset V3.0 rich
transition-level records into machine-learning-oriented tabular
representations.

The published rich transition dataset remains the source of truth. The
scripts are examples, not mandatory preprocessing requirements. Researchers
may implement different feature sets, temporal formulations, targets,
normalization policies, reward definitions, or action spaces for their own
machine-learning, reinforcement-learning, or multi-agent reinforcement-
learning methodology.

The source dataset is read-only. Any files generated by these examples are
local derived artifacts and are not part of the published V3.0 package.

## 2. Available Examples

### `prepare_state_only.py`

`prepare_state_only.py` parses the published processed transition JSONL files
and creates an optional state-only tabular representation. It uses the
following 13 model input features:

```text
active_links
connected_drones
progress_before
position_x
position_y
altitude
speed
direction_x
direction_y
battery
signal_strength
latency
packet_loss
```

The targets are:

```text
next_position_x
next_position_y
```

The following fields are excluded from model inputs:

```text
progress_after
actual_movement
behavior
action
decision
```

The script retains metadata fields separately:

```text
mission_id
mission_type
drone_id
tick
```

The representation is not claimed to be causally valid. Position features
use `state_before.position`, while several physical and network values are
recorded under `state_after`. Researchers must review field timing before
treating this representation as a strict pre-action state.

### `prepare_behavior_aware.py`

`prepare_behavior_aware.py` parses the same rich transitions and creates an
optional behavior-aware tabular representation with 55 model input features:

- 13 base state/context features
- 6 behavior-level telemetry features
- 8 behavior-vector features
- 28 behavior-component features

The six behavior-level features are:

```text
speed_scale
neighbor_count
minimum_neighbor_distance
formation_error
connectivity_risk
boundary_risk
```

The eight behavior-vector features are:

```text
behavior_current_position_x
behavior_current_position_y
behavior_current_velocity_x
behavior_current_velocity_y
behavior_desired_velocity_x
behavior_desired_velocity_y
behavior_movement_vector_x
behavior_movement_vector_y
```

The seven recorded behavior components are:

```text
cohesion
alignment
separation
formation
target_attraction
network_preservation
boundary_avoidance
```

For each component, the representation contains:

```text
x
y
weight
magnitude
```

The targets are:

```text
next_position_x
next_position_y
```

The excluded fields are:

```text
actual_movement
action
decision
progress_after
state_after
```

Advanced Swarm Behavior telemetry is recorded separately from
`actual_movement`. The behavior vectors are telemetry from the scripted
behavior system. They are not reinforcement-learning actions and are not
outputs of a trained model. No causal claim is made for this representation.

## 3. Source Data

The authoritative published processed transition data are located at:

```text
../../data/processed/transitions/*.jsonl
```

The published V3.0 dataset contains:

- 100 missions
- 25 PATROL missions
- 25 SURVEILLANCE missions
- 25 SEARCH missions
- 25 RECOVERY missions
- 11,570 transitions
- 347,100 drone-transition records
- 30 drones per transition
- Advanced Swarm Behavior telemetry in all drone-transition records

At a high level, each transition has this structure:

```text
processed transition
└── swarm
    └── drones[]
        ├── state_before
        ├── state_after
        ├── actual_movement
        └── behavior
```

The scripts treat the source data as read-only. The complete definitions are
provided in:

- [`../../schema/transition_schema.json`](../../schema/transition_schema.json)
- [`../../schema/behavior_schema.json`](../../schema/behavior_schema.json)
- [`../../schema/mission_schema.json`](../../schema/mission_schema.json)

## 4. State-Only Representation

The state-only example uses the exact 13 features listed in Section 2.
`position_x` and `position_y` come from `state_before.position`. The
physical and network values retained by the documented representation,
including altitude, speed, direction, battery, signal strength, latency, and
packet loss, are recorded under `state_after` in the source transition.

The resulting targets are the two coordinates of the recorded
`state_after.position`: `next_position_x` and `next_position_y`.

The script excludes `progress_after`, `actual_movement`, `behavior`, `action`,
and `decision` from model inputs. Metadata identifiers are retained as
metadata and are not converted into numeric model features.

This is an optional derivative representation and is not asserted to be a
strictly causal pre-action state representation.

## 5. Behavior-Aware Representation

The behavior-aware example retains the 13 state/context features and adds
the six behavior-level, eight behavior-vector, and 28 behavior-component
features listed above.

The behavior-component fields are extracted from the recorded Advanced Swarm
Behavior telemetry. They describe recorded behavior information separately
from `actual_movement`. They must not be interpreted as reinforcement-
learning actions or as outputs of a trained policy.

The targets remain `next_position_x` and `next_position_y`. The script
excludes `actual_movement`, `action`, `decision`, `progress_after`, and the
nested `state_after` object from model inputs.

## 6. Temporal Semantics

V3.0 contains fields recorded at different points in a transition:

- `state_before.position` provides the current position used by the
  documented derivatives.
- Several physical and network values are stored under `state_after`.
- Advanced Swarm Behavior telemetry is recorded separately from
  `actual_movement`.
- `actual_movement` is a separately logged movement quantity.
- `next_position_x` and `next_position_y` represent resulting position
  targets from `state_after.position`.
- Action, decision, progress, and other transition fields have their own
  logged semantics.

Researchers must inspect temporal ordering before using these representations
for supervised prediction, causal analysis, reinforcement learning, or
multi-agent reinforcement learning. Fields under `state_after` are not
automatically valid pre-action observations.

## 7. Data Leakage Considerations

The scripts exclude documented outcome, control, and behavior fields according
to each representation's feature schema. They also use mission-level
partitioning rather than randomly splitting individual drone-transition rows.

These precautions do not guarantee that every possible form of leakage has
been eliminated. Researchers should independently review feature timing,
mission structure, target construction, and task formulation before using the
outputs for predictive or causal modeling.

## 8. Recommended Mission-Level Split

Both examples use a deterministic mission-level split:

- Train: 68 missions
- Validation: 16 missions
- Test: 16 missions
- Per mission type: 17 train, 4 validation, and 4 test missions
- Split seed: `20260916`

The previously validated example split produced:

- Train: 234,600 rows
- Validation: 58,860 rows
- Test: 53,640 rows
- Total: 347,100 rows

These row counts are unequal across partitions because missions contain
different numbers of transitions. The CSV files are not included in the final
V3.0 publication package; the counts document the validated example split
only.

Mission-level separation matters because rows from one mission are
temporally and structurally related. Randomly splitting individual rows could
place related observations from the same mission in multiple partitions.

## 9. Running the Examples

From `examples/preprocessing/`, the scripts can be invoked as follows:

```powershell
python .\prepare_state_only.py
python .\prepare_behavior_aware.py
```

To inspect the supported command-line arguments:

```powershell
python .\prepare_state_only.py --help
python .\prepare_behavior_aware.py --help
```

Both scripts support the implemented `--source-root`, `--output-root`, and
`--split-seed` options. For the published package, the source root should
resolve to the package's `data` directory so that the scripts read:

```text
../../data/processed/transitions/*.jsonl
```

Generated outputs are local derived artifacts and are not released as part
of V3.0.

## 10. Reproducibility

The examples use deterministic input-file ordering, sorted mission IDs,
mission-level splitting, deterministic row ordering, and split seed
`20260916`. They validate source structure, required fields, numeric
finiteness, mission assignment, duplicate rows, and transition integrity
before writing outputs.

The scripts do not normalize, standardize, clip, smooth, or impute values.
Researchers should document any additional transformations they apply.

## 11. Output Files

When run locally, each script generates its configured output directory with:

```text
train.csv
validation.csv
test.csv
feature_schema.json
preparation_report.txt
```

The CSV files contain the generated tabular partitions.
`feature_schema.json` describes features, metadata, targets, exclusions, and
split information. `preparation_report.txt` records source coverage,
validation results, and temporal-semantics warnings.

These files are generated local artifacts. The final publication package does
not contain the CSV derivatives or generated ML-ready directories.

```text

        ↓

```

The rich transition data are authoritative. The optional preprocessing

## 13. Recommended Research Use

The examples may support:

- supervised learning experiments
- behavior analysis
- feature engineering
- baseline machine-learning experiments
- state-representation experiments
- custom reinforcement-learning and multi-agent reinforcement-learning
  preprocessing pipelines

These are possible research uses, not demonstrated performance claims. The
dataset is not claimed to be ready for deployment.

## 14. Limitations

- The dataset is simulation-generated, not real-world flight telemetry.
- The mission controller is scripted.
- Advanced Swarm Behavior is scripted behavior telemetry, not a trained
  reinforcement-learning policy.
- Temporal semantics require task-specific review.
- Fields under `state_after` are not automatically pre-action observations.
- Feature exclusion does not guarantee elimination of all data leakage.
- Researchers may need task-specific preprocessing.
- No deployment-readiness claim is made.
- No model-performance claim is made.
- No causal-validity guarantee is made.
